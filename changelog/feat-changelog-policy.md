### Added
- `deskpr create` now applies the `changelog:skip` waiver label to a just-created PR whose ENTIRE diff against the PR base lives under `docs/`, on repos that actually carry the per-PR changelog-fragment gate (detected from the tree: a `changelog/` directory, or a workflow file whose name says changelog). This closes the wait that a documentation-only PR — a board write, an Evidence landing, a docs edit — used to sit in: it ships nothing a changelog entry could truthfully describe, so the only honest fix for the red required check was a waiver the author is not supposed to apply, and the PR waited on a human for a decision nobody disagreed about. The decision here is mechanical ("every changed path is documentation"), never a judgement about whether a change is notable.
- The scope is deliberately narrow and never widens the gate: one path outside `docs/` disqualifies the whole PR, a diff that already carries a `changelog/` fragment is left alone, an ungated repo is left alone, and EVERY read it cannot make fails open to doing nothing — an unreadable diff, an unreadable tree, or a forge that refuses the label all leave the gate exactly as it was, with the PR going red on the ordinary missing-fragment path. The label request runs after the PR already exists and is advisory throughout: it can never turn a create that succeeded into a reported failure. Authority stays where a maintainer puts it — a repo that wants the waiver to remain a human act keeps it one by not granting the PR-opening App `pull-requests: write`, and the request then degrades to a stderr warning naming the gate as still in force.

### Changed
- The `worker-desk` and `pr-shepherd` skill bodies now say which half of the convention a PR owes from its DIFF rather than from taste: a notable code PR ships the fragment, a documentation-only or Evidence-only PR carries the waiver applied at create. `pr-shepherd` additionally tells a shepherd to read the PR's labels BEFORE writing a fragment for it, so a waived documentation PR does not acquire a changelog entry describing a change that is not in its diff.
- The reviewer reference kit's verdict-mechanics clause gains ONE exemption to the same-head APPROVE-after-CHANGES_REQUESTED prohibition: where the only change since the block is a LABEL that turned a required check green, a same-head re-approve is a genuine re-verification and is permitted, provided its body names the label, names the check, and states that the diff is byte-identical to the one reviewed. The clause also states plainly what the exemption does not do — a flip gate compares head shas, a label moves no head, so the flip still refuses on its own terms and clearing the standing rejection remains with whoever owns that gate.
